# Active Upstream Health Monitoring (Parts 2+3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** The gateway discovers each upstream's health endpoint and actively probes it on a cadence, feeding the existing `UpstreamHealthy` EWMA + SiteHealth pipeline so "upstream up but idle" and cold-start are caught (passive EWMA can't see them).

**Architecture:** Two gateway-scoped services. `UpstreamHealthEndpointDiscovery` probes candidate paths per YARP cluster destination (first-200 wins), caches the winner (in-memory + persisted to `ClusterEntity.MetadataJson`). `UpstreamHealthProbeService` runs on a `ScheduleCoordinator` tick, probes the discovered endpoint per cluster, feeds `DegradationAtom.RecordResponse` and persists the last result to `DestinationEntity.Health`. Opt-in.

**Tech Stack:** .NET 10, YARP (`IProxyConfigProvider`), EF Core (`GatewayDbContext`, SQLite), `ScheduleCoordinator`, `DegradationAtom`, xUnit (`Stylobot.Gateway.Tests`), stub `HttpMessageHandler`.

**Spec:** `docs/superpowers/specs/2026-07-07-upstream-health-monitoring-design.md`.

## Global Constraints
- No `BackgroundService` — use `IScheduleCoordinator.Subscribe(TickCadence, name, CostHint, Func<DateTimeOffset, CancellationToken, Task>)`.
- `ConcurrentDictionary` hot cache is fine (derived, re-discoverable), but persist the discovered path to `ClusterEntity.MetadataJson` (survives restart). No em dashes. No hardcoded lists in C# (candidate paths in config).
- Gateway-scoped (`Stylobot.Gateway`); uses core's `ScheduleCoordinator` + `DegradationAtom`. Tests in `Stylobot.Gateway.Tests`.
- **Design decision (supersedes spec §Component-2/4; ratified with overview 2026-07-07, thread `overview-upstream-health-integration-shape`):** active probes are a SEPARATE lane from the passive EWMA. Do NOT call `DegradationAtom.RecordResponse` from the tick: folding synthetic probes into the passive 5xx/4xx EWMA hides outages (a probe passing `/health` while real users 5xx on `/api/*` dilutes the passive signal to "healthy" exactly when it must read "unhealthy") and injects false positives (a transient probe miss flips a clean EWMA). Instead the tick updates an `IActiveUpstreamProbeState` snapshot (lives in core, beside `UpstreamHealthGate`) and persists a JSON health envelope to `DestinationEntity.Health`. `UpstreamHealthGate.IsUpstreamHealthy()` becomes a composite: passive DECIDES when it has samples (`TotalSamples >= MinSampleCount`, preserving passive-unhealthy-dominates-active-healthy), active fills ONLY the cold-start/idle gap (`TotalSamples < MinSampleCount`, where the gate currently returns unconditional-true). No `SignalKeys.UpstreamActiveProbeHealthy` (a tick has no request `SignalSink`); request-time reads come from the service. `DestinationEntity.Health` JSON envelope: `{ "status": "healthy"|"unhealthy"|"unknown", "latencyMs": int, "checkedAtUtc": iso8601, "reason": string|null }`, `{}` before first tick, `null` when never discovered (fits the `HasMaxLength(500)` column).
- Opt-in: `BotDetection:UpstreamHealth:Enabled` default false → the probe service does not subscribe.

## Confirmed seams (verbatim)
- `IProxyConfigProvider.GetConfig().Clusters : IReadOnlyList<ClusterConfig>`; `ClusterConfig.ClusterId`, `.Destinations : IReadOnlyDictionary<string, DestinationConfig>`; `DestinationConfig.Address` (`Stylobot.Gateway/Configuration/YarpConfigProviders.cs`).
- `UpstreamHealthGate` (`src/Mostlylucid.BotDetection/RateLimit/UpstreamHealthGate.cs`): sealed, singleton, pure read over a single process-wide `DegradationAtom` (the PASSIVE lane). `IsUpstreamHealthy()` is PARAMETERLESS: returns true while `_atom.TotalSamples < opts.MinSampleCount` (cold-start protection), else checks `Error5xxRate`/`Error4xxRate` EMA thresholds. Ctor `(DegradationAtom, IOptions<UpstreamHealthOptions>)` + a `WithMonitor` factory + a private `IOptionsMonitor` ctor + existing `UpstreamHealthGateTests` construct it 2-arg. The `TotalSamples < MinSampleCount` branch is the active lane's insertion point.
- `DegradationAtom` (`src/Mostlylucid.BotDetection/RateLimit/DegradationAtom.cs`): `long TotalSamples`, `double GetSignalValue(string)`, `RecordResponse(int,long,string)`. The tick does NOT call `RecordResponse` (separate lane — see Global Constraints).
- `ClusterEntity.MetadataJson : string?` (holds discovery's `healthEndpoint` key), `DestinationEntity { ClusterId, DestinationId, Address, Health : string?, MetadataJson : string? }` (`Stylobot.Gateway/Data/GatewayDbContext.cs:105-129`; `Health` `HasMaxLength(500)`). `AdminEndpoints.cs:312` already surfaces `d.Value.Health` raw — Task 5 updates it to parse the envelope.
- `IScheduleCoordinator.Subscribe(...)` returns `IDisposable` (`Mostlylucid.Common/Scheduling/IScheduleCoordinator.cs:94`); cadences in `TickCadence`.
- Gateway DbContext is registered SCOPED (`AddDbContext<GatewayDbContext>`, no `IDbContextFactory`); singleton services reach it via `IServiceScopeFactory` + `CreateScope()` (precedent: `Stylobot.Gateway/Services/ProfileAnalysisWorker.cs`).

### Task 3: Active-probe state abstraction (core) + `UpstreamHealthGate` composite

**Interfaces — Produces:**
- `public sealed record ActiveProbeSnapshot(string Status, int LatencyMs, DateTimeOffset CheckedAtUtc, string? FailureReason)` — `Status` one of `"healthy"`/`"unhealthy"`/`"unknown"`; `FailureReason` non-null only when `Status != "healthy"`.
- `public interface IActiveUpstreamProbeState { void Update(string upstreamKey, ActiveProbeSnapshot snapshot); ActiveProbeSnapshot? Latest(string upstreamKey); bool? - `ActiveUpstreamProbeState` — default impl backed by `ConcurrentDictionary<string, ActiveProbeSnapshot>`. Registered in core DI via `TryAddSingleton<IActiveUpstreamProbeState, ActiveUpstreamProbeState>()` so non-gateway hosts resolve an empty state (`AggregateHealthy()` → null → gate keeps cold-start-true). The gateway host reuses this same impl (the tick writes into it).
- `UpstreamHealthGate` gains an OPTIONAL ctor param `IActiveUpstreamProbeState? probeState = null` (nullable + default so the existing 2-arg `UpstreamHealthGateTests` constructions still compile; DI injects the registered singleton). Composite `IsUpstreamHealthy()`: `if (_atom.TotalSamples >= opts.MinSampleCount) { <existing 5xx/4xx threshold verdict> } return _probeState?.AggregateHealthy() ?? true;`. Thread the optional param through `WithMonitor` + the private `IOptionsMonitor` ctor too.
- **Required `<remarks>` doc (overview's ratification ask):** put a `<remarks>` block on `AggregateHealthy()` AND on the gate composite explaining the worst-case fold — one known-unhealthy upstream makes the whole gate report unhealthy — is correct because `UpstreamHealthGate.IsUpstreamHealthy()` feeds `ResponseBehaviorAtom`'s decision to trust response-shape-derived signals; any upstream degradation makes those shape signals unreliable, so pessimism is the safe default. ~5 lines; stops the next author second-guessing "why did one 500-ing sidecar suppress the whole pipeline's shape signals."
