# Centroid Persistence on WriteBehindLfuStore (finish the unfinished feature) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Finish the centroid-persistence feature by putting the three centroid stores on the canonical `WriteBehindLfuStore` (the same prioritized-sampling single-writer pattern the rest of the system uses: `SqlitePoolCollisionStore`, `SqlitePathLifecycleStore`, `SqliteStickyDenyStore`, `WaveformHistoryStore`), and WIRING them as the real default — replacing the dead null-store defaults and the bespoke channel writer that was architectural drift.

**Architecture:** Each centroid store becomes `WriteBehindLfuStore<string, TEntry, TWriteOp>`. `Record(signature, op)` on the hot path (non-blocking, no `Task.Run`); `ColdnessScore` = `DecisionNecessity.ColdnessScore(...)` so eviction under cap/memory-pressure sheds the LEAST decision-necessary centroids first (the prioritization shaping); `PersistBatchAsync` is one batched transaction per drain interval (single-writer, `_writeLock`); `MergeIntoExisting` dedups by signature; the cap comes from `SelfMaintenanceOptions.{Signature,Session,Intent}CacheSize` with an optional `MemoryAdaptiveCap` provider. Wired as the default in the SQLite path; null variants only under `AddBotDetectionInMemory`. The `Slim*` searches call `Record(...)` directly.

**Tech Stack:** C#/.NET 10, `Mostlylucid.BotDetection.Storage.WriteBehindLfuStore`, `Storage.DecisionNecessity`, `Storage.MemoryAdaptiveCap`, `Microsoft.Data.Sqlite`, `Data.Schema.SchemaLoader`, xUnit + in-memory SQLite.

## Global Constraints (binding)
- **Use `WriteBehindLfuStore`, do NOT roll a bespoke channel/drain.** The rest of the system is the reference (`Identity/SqlitePoolCollisionStore.cs` is the exact template — read it first).
- **`ColdnessScore` = `DecisionNecessity.ColdnessScore(botProbability, threat, ageSeconds, threshold, halfLifeSeconds)`** ("lower = colder = evicted first") — this is the prioritization shaping the operator required. Not `DropOldest`, not FIFO.

- **Cap from `SelfMaintenanceOptions`** (`SignatureCacheSize`=5000, `SessionCacheSize`=2000, `IntentCacheSize`=1000) + optional `MemoryAdaptiveCap` via the `maxEntriesProvider` ctor arg.

- **DELETE the drift**: `Data/Centroids/SqliteCentroidWriter.cs`, `ICentroidWriter.cs`, `CentroidWriteMessage.cs`, `NullCentroidWriter.cs`, `CentroidWriterOptions.cs`, and Task 2's `(SqliteConnection conn, ...)` overloads if unused — remove them and their registrations/tests.
